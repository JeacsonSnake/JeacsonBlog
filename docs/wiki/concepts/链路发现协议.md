# 链路发现协议（LLDP）

## 核心结论

> LLDP（Link Layer Discovery Protocol）定义在 **IEEE 802.1ab**，是**二层**协议。它解决的是「我不知道对面那台设备是谁」这个问题：每台设备周期性地把自己的**能力、管理地址、设备标识、接口标识**发给同一局域网的其它设备。
>
> 关键限制：**LLDP 只做信息通告**。它提供拓扑与管理配置信息，供管理与配置使用，但**不能通过它去配置远端设备**。

## 一、为什么需要它

异构组网里，交换机、路由器、AP、服务器来自不同厂商，二层邻居关系没有统一的自描述机制。SNMP 只能查到「我这个设备上有什么」，查不到「我这个端口连的是谁」。LLDP 补的正是这块：

- 与厂商无关（对标思科私有的 CDP）；
- 只依赖二层可达，不需要 IP 层就能交换信息（虽然管理地址也是通告内容之一）；
- 信息可被网管系统（NMS）汇总，自动画出物理拓扑。

## 二、通告什么

标准化的 TLVs 覆盖四类信息（原文概括为「能力、管理地址、设备标识、接口标识」）：

| 信息 | 用途 |
|---|---|
| 设备标识（Chassis ID） | 对面是谁 |
| 端口标识（Port ID） | 从哪个口出来的 |
| 生存时间（TTL） | 多久没更新即认为邻居失效 |
| 系统名称/描述/能力 | 设备类型与能力集（桥、路由、AP…） |
| 管理地址 | 可用于进一步管理（如 SNMP 目标） |
| 端口描述、VLAN 名等可选 TLV | 运维排障上下文 |

行为特征：

- **周期性**发送（默认间隔常见 30 秒，TTL 为其数倍），只发给**直连**邻居（目的 MAC 为 `01:80:C2:00:00:0E`），不跨设备转发；
- 收到的信息存入 **LLDP 邻居表**，老化后删除；
- 可以只发不收（ transmit-only）、只收不发（receive-only）双向控制，排障时先确认端口 LLDP 工作模式。

## 三、边界：能做什么、不能做什么

- ✅ 还原二层拓扑、定位「这个口接的是哪台设备的哪个口」、核对链路两端配置是否匹配（VLAN、速率双工）；
- ✅ 作为网管系统自动发现的基础数据；
- ❌ **不能**通过 LLDP 修改远端设备的任何配置（没有写操作，也没有认证/授权模型）；
- ❌ **不是**发现协议里的路由/邻居协议（OSPF/IS-IS 那类属于三层）。

## 四、常见排障误区

- 交换机看不到邻居 → 对端可能是服务器/虚拟化环境，默认没开 LLDP，需要装 `lldpad`/`lldpd` 并启用；
- 能看到邻居但拓扑画错 → 中间有**不支持 LLDP 透传**的设备（部分 media converter、非网管交换机）;
- LLDP 报文被安全策略丢弃 → 有的接入层会禁用 LLDP 防信息泄露，此时拓扑发现会缺边。
