# WiFi 5GHz DFS 信道雷达避让 — 社交平台图片加载缓慢排查

## 核心结论

> **5GHz 的 52~140 信道属于 DFS（Dynamic Frequency Selection）频段，法规要求 AP 检测到雷达信号时必须静默并切换信道，期间客户端传输会被挂起** → 表现为不定时、无规律的卡顿。图片加载是大量小请求，对链路抖动极敏感（视频有缓冲可掩盖抖动，图片仅在点击大图时才加载）→ "视频正常、图片卡"。手动切换频段（2.4G ↔ 5G）强制重连后立即恢复，是因为重连后 AP 落到非 DFS 信道或避让期结束。

## 故障现象

家庭 WiFi 同时提供 2.4GHz 与 5GHz（Linksys Velop Pro 7），手机默认连 5GHz，浏览社交平台（X、微博等）时**不定时**图片加载缓慢：

- 视频可正常播放，仅图片加载慢（缩略图慢 / 点击大图长时加载）
- 用户头像疑似"不被缓存"，反复浏览同一用户也需重新加载
- **手动切换频段（2.4G ↔ 5G）后问题立即消失**（关键线索）

路由器内设置手机优先规则无效 → 恢复原设置后开始排查。

## 排查过程（分层排除）

用 Network Analyzer Lite 在 5GHz 下分层测试：

| 测试项 | 结果 | 排除的变量 |
|---|---|---|
| ping 网关 192.168.1.1 | 0 丢包，14~32ms（有抖动，略偏高） | 局域网/信号质量基本正常 |
| ping weibo.com / sinaimg CDN / x.com | 正常，8~67ms | DNS 解析、外网连通性、CDN 路由 |
| WiFi 参数 | 802.11be，-58/-59 dBm，协商速率 1441/1152 Mbps | 信号强度 / 协商速率 |
| DNS | 路由器代理，无公网 IPv6 | DNS 因素 |

网络健康全链路无异常 → 在 Info 页发现 **5GHz 频段使用的信道为 100（5500 MHz），处于 DFS 信道**。

## 根因：DFS 信道雷达避让机制

5GHz 的 **52~140 信道为 DFS 频段**，法规要求 AP 检测到雷达信号时**必须静默并切换信道**，期间客户端传输被挂起 → 不定时、无规律卡顿。

图片与视频的差异解释了症状：图片加载是大量小请求、对链路抖动敏感；视频播放时有缓冲可掩盖抖动，且图片仅点击大图时才加载。切换频段强制重连之所以"有效"，是因为重连过程避开了避让窗口（2.4G 全部为非 DFS 信道）。

## 解决方案：关闭 DFS

该 Velop 系列路由器**不支持手动指定具体信道** → 直接"关闭 DFS"：

Linksys App → ☰ → Wi-Fi 设置 → 高级 Wi-Fi 设置 → 关闭 DFS

关闭后路由器只使用非 DFS 信道（**36~48 / 149~165**），避免雷达避让。再运行一次 **Channel Finder** 在非 DFS 范围内自动选择干扰最小的信道——本次最终落地信道 **161（5805 MHz）**。

## 经验总结

1. **"视频正常、图片卡"是链路抖动的典型症状分化**：小请求对抖动敏感，有缓冲的流媒体可掩盖 → 先别怀疑 CDN/DNS，检查无线链路本身。
2. **切一下频段就好 ≠ 玄学修复**：强制重连绕过了避让窗口；结合 Info 页的信道号即可定位 DFS。
3. **DFS 信道是家用路由器的隐性坑**：52~140 默认可能被 AP 自动选中，雷达避让导致的卡顿与信号强弱无关，常规网络测试（ping/DNS/CDN）全部正常也不矛盾。
4. **不支持手动指定信道的路由器 → 关 DFS + Channel Finder**：让 AP 在 36~48 / 149~165 内自动选干扰最小的信道。
