## 📄 arXiv Papers — cs.AI / cs.LG / cs.CL

- **[On Turn-Level Best-of-N Sampling for Scaling LLM Agents](https://arxiv.org/abs/2611.06868)** | cs.AI | Jalaj Bhandari, Dhawal Gupta
  Proposes "turn-level best-of-N" inference-time scaling: at every step the generator model produces N candidate actions and a selector model picks one to execute. On long-horizon terminal tasks it lifts accuracy by 5–10%, with better consistency across repeated runs.
- **[FrontierPhysics: Evaluating Agents for End-to-End Physics Research](https://arxiv.org/abs/2611.06910)** | cs.AI | Bingran You, Wenjun Ke
  A 56-task end-to-end research benchmark written by 42 physicists, covering nine directions across theory / computation / experiment and checking both correctness and "publishability". Across 22 models in 26 configurations, no configuration passed more than 46 of 168 runs; the main weakness is insufficiently rigorous reasoning and a lack of expert intuition, not knowledge or execution errors.
- **[CompressionBench: How can your coding agents compress LLMs?](https://arxiv.org/abs/2611.06858)** | cs.AI | Xinrui Zhong, Zhifeng Li
  Turns model compression into a terminal task: can a coding agent compress a model autonomously and hand back runnable inference code? Across 6 agents × 6 scale settings, 29/36 submissions validated, and the best design averaged perplexity only 3.4% above BF16.
- **[SpecCompact: Accelerating LLM Agent Context Compaction with Slot-Parallel Semantic Speculative Verification](https://arxiv.org/abs/2611.06876)** | cs.CL | Yulu An, Yifei Feng
  A small drafter generates structured summary slots in parallel while the target model verifies and repairs them line by line, speeding up agent context compaction by 2.04–5.63× (median 8.68× in an internal Hermes user study).
- **[ServerBench: How can your coding agents design specialized LLM serving systems?](https://arxiv.org/abs/2611.06841)** | cs.AI | Xinrui Zhong, Zhiming Wang
  Has coding agents design an inference serving system end to end, with a single objective: the value of latency-compliant tokens per dollar of GPU cost. 22 of 33 runs produced validated systems and 13 beat the strongest baseline; Claude Sonnet 5.5 reached 4.87× the vLLM reference implementation on Gemma E4B.
