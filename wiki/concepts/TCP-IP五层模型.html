TCP/IP 五层模型

核心结论

分层的意义是每层只解决一个维度的送达问题：物理层把比特变成信号，链路层解决「同一链路内送到哪块网卡」，网络层解决「跨网络送到哪台主机」，传输层解决「送到哪个进程」，应用层解决「这段字节是什么意思」。

层职责关键实体/协议

逐层要点

物理层

把数据包转换成电信号，使其能在物理介质中传输，为链路层提供二进制传输服务。

数据链路层（MAC 层）

数据跨网络传输时必须知道「这个物理地址属于哪台设备」，于是需要一层专门标识链路内设备 —— 这就是链路层。它主要解决媒体接入控制，所以其地址常被称为 MAC（Media Access Control）地址，这一层也因此被叫作 MAC 层。

  • ARP 的作用：通过 IP 查 MAC。交换机（二层设备）拿着目的 IP 发 ARP 请求，目标设备回 ARP 应答，交换机由此知道「这个 IP 在哪个端口后面」。
  • 交换机把学到的映射记下来，形成转发表；由于 IP 与端口会变，转发表有老化时间，超时即失效。

网络层（IP 层）

负责把数据从一台设备送到另一台设备，最常用的协议就是 IP。IP 把传输层交下来的报文当作数据部分，加上 IP 报头组成 IP 报文；若超过 MTU（以太网通常 1500 字节） 就分片。

寻址与转发：

  • 同网段：源设备把源/目的 IP 写进 IP 头，用 ARP 得到目的 MAC，把源/目的 MAC 写进帧的 MAC 头直接转发。
  • 跨网段：源设备把包发给默认网关（与源 IP 同网段，通常是三层设备路由器）。路由器用路由表按目的 IP 找到下一跳，逐跳转发；最后一跳发现目的 IP 在自己网段内，再用 ARP 取得目的 MAC、改写目的 MAC 后发出。

这一过程叫三层转发。一句话区分：IP 寻址告诉我们往哪个方向走（导航），路由是选择哪个路由器（方向盘）。

传输层

为应用层提供网络支持，负责两台主机中进程之间的通信，两个协议是 TCP 与 UDP：

  • TCP（Transmission Control Protocol）：面向连接、可靠、基于字节流。
  • UDP（User Datagram Protocol）：无连接、面向事务、简单不可靠。

应用层

我们直接接触的软件都在这一层。应用把数据交给传输层，只关注功能而不关心传输细节；为协助传输，这一层提供了 HTTP、HTTPS、DNS、FTP 等协议。

用一次访问串起来

浏览器 https://example.com
  ↓ 应用层：DNS 解析域名 → 生成 HTTP 请求
  ↓ 传输层：TCP 三次握手，加端口
  ↓ 网络层：查路由，判断是否同网段，加 IP 头（必要时分片）
  ↓ 链路层：ARP 得到下一跳 MAC，加帧头
  ↓ 物理层：变成电信号/光信号
